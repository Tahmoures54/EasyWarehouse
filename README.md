# انبارداری آسان

برنامه دسکتاپ «انبارداری آسان» برای مدیریت کالا و گردش انبار، با Python/Tkinter و SQLite. نسخه کد فعلی: **1.2.0**. مخزن: https://github.com/Tahmoures54/EasyWarehouse

> وضعیت انتشار: وجود سورس و workflow به‌تنهایی به معنی تأیید پروداکشن نیست. قبل از اعلام انتشار، وضعیت آخرین اجرای GitHub Actions و آزمایش دستی EXE روی ویندوز تمیز را بررسی کنید.

## امکانات
- تعریف و ویرایش کالا با کد انتخابی کاربر، دسته‌بندی و حداقل موجودی
- هشدار برای کد یا نام تکراری؛ ثبت پس از تأیید کاربر مسدود نمی‌شود
- ثبت ورود، خروج و عودت و محاسبه موجودی از روی گردش تراکنش‌ها
- هشدار کاهش موجودی و جلوگیری پیش‌فرض از خروج بیش از موجودی
- گزارش وضعیت موجودی و فهرست کالاهای کم‌موجودی/ناموجود به CSV سازگار با Excel
- گزارش گردش و تاریخچه تراکنش‌ها با امکان فیلتر بازه تاریخ و کد کالا در لایه گزارش
- نمایش آخرین تاریخ گردش، کسری نسبت به حداقل موجودی و وضعیت هر کالا در گزارش موجودی
- ذخیره دیتابیس در پوشه داده کاربر؛ مسیر قدیمی `%APPDATA%\\EasyWarehouse\\anbar.db` برای حفظ اطلاعات نصب‌های قبلی عمداً ثابت مانده است.
- پشتیبان‌گیری و بازیابی همراه با اعتبارسنجی SQLite و نسخه احتیاطی
- رابط فارسی و راهنمای کاربر با F1

## سیاست موجودی
- سیاست پیش‌فرض ALLOW_NEGATIVE_STOCK = False است؛ خروجی که موجودی را منفی کند ثبت نمی‌شود.
- برای سناریوهایی که موجودی منفی عمداً مجاز است، مقدار این تنظیم در app/config.py باید صریحاً به True تغییر کند. این تغییر سیاست کسب‌وکار است و باید پیش از توزیع مستند و آزمایش شود.
- تاریخ تراکنش فقط با قالب معتبر میلادی YYYY-MM-DD پذیرفته می‌شود، مانند 2026-10-19.
- مقدار تراکنش باید عددی متناهی و بزرگ‌تر از صفر باشد. حذف تراکنش موجودی را از روی تراکنش‌های باقی‌مانده دوباره محاسبه می‌کند.

## اولین اجرا و داده نمونه
برنامه به‌صورت پیش‌فرض با انبار خالی شروع می‌شود. هیچ کالای نمونه‌ای خودکار به دیتابیس کاربر اضافه نمی‌شود؛ این تصمیم از اشتباه گرفتن داده آزمایشی با موجودی واقعی جلوگیری می‌کند. ماژول app/services/seed.py برای آزمایش/توسعه در دسترس است، اما از اجرای اصلی فراخوانی نمی‌شود.

## کاربران و امنیت محلی

- در نخستین اجرا، فرم راه‌اندازی برای ساخت حساب مدیر نمایش داده می‌شود؛ نام کاربری و رمز عبور را به خاطر بسپارید.
- رمز عبور به‌صورت متن ساده ذخیره نمی‌شود؛ از PBKDF2-HMAC-SHA256 با salt تصادفی استفاده می‌شود. رمز باید حداقل ۱۰ نویسه و شامل حرف و عدد باشد.
- نقش‌ها: مدیر (مدیریت کاربران، پشتیبان‌گیری/بازیابی و حذف)، انباردار (ثبت و اصلاح کالا و تراکنش‌ها) و مشاهده‌گر (دسترسی مشاهده و گزارش).
- پس از پنج تلاش ناموفق، ورود حساب برای ۱۵ دقیقه قفل می‌شود. حساب مدیر می‌تواند رمز کاربران را بازنشانی و حساب‌ها را غیرفعال کند؛ آخرین مدیر فعال قابل حذف/تنزل نقش نیست.
- رویدادهای ورود، تغییر حساب‌ها، دسترسی ردشده و ثبت موفق تراکنش در جدول محلی حسابرسی ثبت می‌شوند.
- جداول کاربران و حسابرسی به‌صورت افزایشی به دیتابیس موجود اضافه می‌شوند و داده‌های فعلی کالاها و تراکنش‌ها حذف نمی‌شوند.
- این کنترل‌ها برای استفاده عادی از برنامه دسکتاپ طراحی شده‌اند؛ دسترسی مستقیم سیستم‌عامل به فایل SQLite یا نسخه‌های پشتیبان، خارج از کنترل برنامه است. از فایل دیتابیس و پشتیبان‌ها محافظت کنید.

## اجرا از سورس
نیازمندی‌ها: Python 3.10 یا جدیدتر. Tkinter و SQLite در نصب استاندارد Python معمولاً موجودند.

```bash
python -m venv .venv
# Windows:
.venv\\Scripts\\activate
# Linux/macOS:
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m app.main
```

## اجرای تست‌ها
```bash
python -m pip install -r requirements.txt
python -m pytest -v --junitxml=test-results.xml
```
GitHub Actions تست‌ها را روی Ubuntu و Windows اجرا می‌کند. وضعیت اجرای واقعی را در تب Actions ببینید؛ تا وقتی آخرین اجرای مربوط به commit موردنظر موفق نشده، آن را سبز تلقی نکنید.

## ساخت EXE ویندوز
روی ویندوز با Python نصب‌شده، scripts\\build_windows.bat را اجرا کنید.

یا اجرای مستقیم PyInstaller:
```powershell
python -m pip install -r requirements.txt
python -m PyInstaller --noconfirm --clean --onefile --windowed --name AnbardariAsan --add-data "app/database/schema.sql;app/database" --add-data "assets;assets" app/main.py
```
خروجی مورد انتظار dist/AnbardariAsan.exe است. workflow در GitHub Actions، پس از موفقیت تست‌ها، فایل اجرایی را با نام artifact AnbardariAsan-Windows-x64 منتشر می‌کند. Artifact با GitHub Release عمومی یکسان نیست؛ برای انتشار عمومی باید آن را به Release متصل کنید.

## گزارش کاردکس کالا

- از منوی «گزارش‌ها» گزینه «کاردکس کالا» را باز کنید و کالا را انتخاب کنید.
- گردش‌ها به ترتیب زمانی همراه با ورود، خروج و مانده تجمعی نمایش داده می‌شوند؛ با تعیین بازه تاریخ، مانده ابتدای دوره از تمام گردش‌های قبل از شروع محاسبه می‌شود.
- بازه تاریخ را می‌توان شمسی (مانند ۱۴۰۵/۰۷/۲۹) وارد کرد؛ برای سازگاری، قالب ISO میلادی نیز پذیرفته می‌شود.
- فیلتر نوع گردش (همه، ورود، خروج یا عودت) در جدول و خروجی CSV اعمال می‌شود؛ مانده هر ردیف همچنان بر اساس تمام گردش‌های واقعی محاسبه می‌شود.
- گزارش چاپی HTML با صفحه‌آرایی افقی A4 و گزینه چاپ/ذخیره PDF از طریق مرورگر ارائه می‌شود.
- کد داخلی و کد انتخابی کالا پذیرفته می‌شوند. گزارش را می‌توان با CSV سازگار با Excel ذخیره کرد.
- کاردکس از تراکنش‌های واقعی دیتابیس محاسبه می‌شود و موجودی را تغییر نمی‌دهد.

## کنترل موجودی و شمارش فیزیکی

- گزارش کالاهای راکد با موجودی مثبت (پیش‌فرض: بدون گردش طی ۹۰ روز) در منوی «گزارش‌ها» قابل خروجی CSV است؛ موجودی صفر از گزارش راکد حذف می‌شود.
- برگه شمارش فیزیکی، کد کالا، نام، قفسه و موجودی سیستمی را به CSV صادر می‌کند و ستون‌های تعداد شمارش‌شده، اختلاف و توضیح را خالی می‌گذارد تا انباردار تکمیل کند.
- برگه شمارش CSV یک برگه کاری مستقل است و به‌تنهایی موجودی را تغییر نمی‌دهد.
- برای ثبت شمارش واقعی از «ثبت شمارش و تعدیل موجودی» استفاده کنید. تعداد شمارش‌شده می‌تواند صفر باشد؛ علت اجباری است و اختلاف پیش از ثبت برای تأیید نمایش داده می‌شود.
- تعدیل به‌صورت گردش ورود/خروج ثبت می‌شود و جدول مستقل، موجودی سیستمی، تعداد شمارش‌شده، اختلاف، علت، کاربر، زمان و شناسه گردش را نگه می‌دارد. رویداد حسابرسی نیز ثبت می‌شود.
- ثبت تکراری با مرجع یکسان رد می‌شود؛ اگر موجودی از زمان بازشدن فرم تغییر کرده باشد، ثبت متوقف می‌شود تا شمارش دوباره بررسی شود. فقط مدیر و انباردار مجازند؛ مشاهده‌گر اجازه ثبت ندارد.

## چاپ رسید و حواله کالا

- از جدول «گردش کالاها» یک ردیف را انتخاب و «چاپ رسید / حواله» را بزنید؛ همین فرمان در منوی «گزارش‌ها» نیز در دسترس است.
- ورود به‌صورت رسید ورود، خروج به‌صورت حواله خروج و عودت به‌صورت رسید عودت چاپ می‌شود.
- سند شامل شماره قابل ردیابی بر اساس شناسه گردش، تاریخ خورشیدی، کد و نام کالا، مقدار/واحد، توضیحات و نام ثبت‌کننده است؛ بخش امضای تحویل‌دهنده و تحویل‌گیرنده هم دارد.
- سند در مرورگر پیش‌فرض باز می‌شود و پنجره چاپ برای چاپگر یا ذخیره PDF ارائه می‌گردد. نسخه HTML در پوشه `printouts` کنار دیتابیس کاربر ذخیره می‌شود.
- چاپ، گردش یا موجودی را تغییر نمی‌دهد. شماره سند چاپی شناسه همان گردش است، نه شماره مستقل دفتر اسناد.

## گزارش‌گیری
از منوی «گزارش‌ها» می‌توان گزارش وضعیت فعلی موجودی، کم‌موجودی/ناموجودی و گردش تراکنش‌ها را به CSV صادر کرد. فایل‌ها با UTF-8 BOM ذخیره می‌شوند تا متن فارسی در Excel بهتر نمایش داده شود. موجودی گزارش از تراکنش‌های ثبت‌شده محاسبه می‌شود؛ مقدار موجودی جداگانه و دستی ذخیره نمی‌شود.

## پشتیبان‌گیری و بازیابی
1. قبل از بازیابی، برنامه را ببندید تا فایل دیتابیس در حال استفاده نباشد.
2. از منوی «پرونده ← پشتیبان‌گیری» یک نسخه در پوشه‌ای جدا، ترجیحاً روی رسانه/دیسک دیگر، ذخیره کنید.
3. برای بازیابی، فایل .db، .sqlite یا .sqlite3 را انتخاب کنید.
4. برنامه قبل از جایگزینی، سلامت SQLite و ساختار جدول‌های کالا و تراکنش را بررسی می‌کند. فایل خالی، خراب یا با ساختار نامرتبط رد می‌شود.
5. در صورت وجود دیتابیس فعلی، یک نسخه احتیاطی با نامی مانند anbar.db.pre_restore_YYYYMMDD_HHMMSS_microseconds.bak کنار دیتابیس ساخته می‌شود.
6. بازیابی از فایل موقت و جایگزینی اتمی استفاده می‌کند؛ با این حال، پشتیبان‌گیری منظم و نگهداری نسخه‌ای خارج از دستگاه همچنان ضروری است.

## محدودیت‌های تأیید
- ساخت موفق EXE در CI، به‌تنهایی اثبات اجرای صحیح رابط گرافیکی روی همه نسخه‌های ویندوز یا نبود هشدار آنتی‌ویروس نیست.
- آزمون دستی روی Windows تمیز، بدون Python، باید جداگانه ثبت شود؛ تا پیش از انجام آن، این بخش تأییدنشده است.
- این برنامه چندکاربره/شبکه‌ای نیست و برای استفاده همزمان چند کاربر روی یک فایل SQLite طراحی نشده است.
- نسخه پشتیبان را به‌طور دوره‌ای روی یک مسیر جدا نگهداری و امکان بازیابی آن را آزمایش کنید.

## کدگذاری کالا

کد نمایشی کالا را کاربر وارد می‌کند و می‌تواند تکراری باشد؛ برنامه برای هر رکورد یک شناسه داخلی مستقل می‌سازد تا گردش‌های ورود و خروج به کالای صحیح متصل بمانند. تکرار کد یا نام کالا (با نادیده گرفتن فاصله‌های اضافی و تفاوت برخی حروف عربی/فارسی) هشدار داده می‌شود، اما پس از تأیید کاربر مانع ثبت دستی یا ورود Excel نیست. الگوی Excel نیز ستون «کد کالا» را دارد.
